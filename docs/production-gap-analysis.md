# AdFlux 与真实商用广告系统的剩余差距

本文用于界定当前本地沙盘的能力边界。工作台已经形成可运行的数据闭环，但不应未经下面的生产化建设直接承载真实广告交易。

## 已形成闭环的能力

- D1 真实广告库存、计划、账户、广告位和请求日志。
- 多路召回、过滤、粗排、精排、多计费模式 eCPM 和拍卖。
- 用户 24 小时真实曝光频控。
- CPM/oCPM 曝光、CPC 点击、CPA 转化的预算预占与清算。
- 曝光、点击、转化顺序校验、归因窗口和幂等写入。
- 资金账本、拍卖、事件、实验分桶和后台操作不可变记录。
- 策略草稿、版本激活、生产默认版本和操作审计。
- 用户稳定 A/B 分桶及真实请求/事件指标。
- 数据一致性检查、过期预占释放、请求全链路追踪和风险扫描。
- 黄金召回用例服务端回放（D1 真实库存 + 生产策略版本）、自定义质量门槛和 JSON 报告。
- Campaign asap/even 分时匀速 Pacing，按上海投放日线性控制预算消耗。
- 基于真实 Worker 调用与内存 D1 的行为级集成测试，锁定资金、幂等和审计闭环。

## P0：上线前必须补齐

### 身份认证与权限

当前管理接口用 `X-Operator` 标记操作者，但没有验证身份。生产环境需要统一登录、RBAC、广告主数据隔离、敏感操作二次确认和服务间身份认证。

### 接口安全

需要 API 签名、时间戳与 nonce、防重放、租户级限流、请求体大小限制、WAF、密钥轮换和完整的安全审计。追踪 token 需要可撤销、短期签名且不能只依赖随机字符串。

### 高可用与扩展

当前单 Worker + D1 适合演示，不是百万广告毫秒召回架构。生产链路通常需要多区域服务、服务发现、熔断降级、超时预算、缓存、倒排索引/向量召回、流式特征、模型服务和跨机房容灾。

### 资金系统

需要独立资金账户体系、双重记账、日切、对账、发票/税务、退款与调账审批、信用额度、币种与汇率、财务报表以及资金操作权限隔离。

### 隐私与合规

需要用户同意管理、数据最小化、地域数据驻留、删除/导出请求、敏感字段加密、保留期策略、未成年人规则和适用地区的广告隐私法规评审。

## P1：规模化投放所需

### 广告审核与素材

当前没有素材上传、自动审核、人工复审、行业资质、落地页检测、敏感词/图片识别、版本审核和拒审申诉。

### 定向与频控

需要人群包、排除人群、地域层级、时间段、应用版本、网络、运营商、设备价格段、跨端身份、Campaign/广告主多层频控，以及低延迟分布式计数器。

### Pacing 与流量预估

当前支持 asap/even 两种模式和按投放日线性放量的匀速上限。生产还需要流量预测、PID 或模型控制、冷启动、欠投补偿和大促保护。

### 模型与特征平台

当前 pCTR/pCVR 是库存字段。生产需要在线特征、训练样本、特征一致性、模型注册、版本、灰度、校准、漂移检测、回滚和 GPU/CPU 推理服务。

### 实验平台

需要实验互斥层、流量域、样本量估算、显著性检验、序贯检验、护栏指标、SRM 检测、自动停止和长期效应分析。

## P2：运营效率与商业能力

- 广告主自助平台开户、合同、充值、账单和权限协作。
- Campaign/广告组/创意完整层级和批量编辑。
- 转化价值、ROAS、深度转化、离线转化回传和增量归因。
- 品牌安全、库存质量、无效流量供应商集成和申诉工作流。
- 预测报表、维度下钻、定时报表、数据导出和告警通知。
- 多广告槽位、保量合约、PMP、优先级交易和收益管理。

## 推荐下一阶段

1. 先接入本地身份与角色权限，让所有管理修改具备可信操作者（`app/chatgpt-auth.ts` 已有现成辅助函数）。
2. 在现有 even Pacing 基础上补流量预测与 PID 控速，替换线性放量曲线。
3. 引入 Redis 类低延迟计数器与倒排索引，做百万级库存压测。
4. 建立素材审核和落地页安全链路。
5. 为实验加入 SRM、显著性、护栏和自动回滚。

每个阶段都应保留当前的幂等、不可变审计、健康检查和端到端验收原则。
