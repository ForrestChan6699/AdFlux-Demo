# AdFlux 本地运营与验收手册

## 1. 访问入口

本地服务启动后访问 `http://localhost:3000`。顶部工作台按真实业务职责划分：

- 决策：发起服务端广告请求，查看五阶段候选和决策诊断。
- 策略：调整参数、保存草稿、激活生产版本。
- 投放：管理广告、计划、账户信息、广告位和拍卖底价。
- 归因：使用本次请求的签名链接上报真实事件。
- 风控：扫描真实请求和事件中的异常链路。
- 实验：查看稳定分桶和真实聚合指标。
- 召回测试：执行黄金场景与自定义场景。
- 运行健康：检查数据一致性、预算安全和请求全链路。
- 监控：查看 D1 最近请求和 24 小时聚合数据。

## 2. 推荐验收顺序

### 2.1 服务端决策

1. 在“决策”选择城市、设备、信息流/视频流和兴趣。
2. 点击右上角“运行请求”。
3. 确认生成 `req_...` 请求编号。
4. 逐个打开召回、过滤、粗排、精排、计费。
5. 检查阶段实际耗时、过滤原因和填充结果。

信息流自动使用 `feed_home` GSP；视频流自动使用 `video_recommend` 一价拍卖。

### 2.2 事件与计费闭环

1. 完成一次广告请求后进入“归因”。
2. 按曝光、点击、转化的顺序触发事件。
3. 确认事件进入数据库，重复点击同一按钮不会重复计费。
4. 进入“运行健康”，输入请求 ID 查询全链路。
5. 检查请求、拍卖、预算预占、事件和账本五个节点。

CPM/oCPM 在曝光确认，CPC 在点击确认，CPA 在转化确认。

### 2.3 用户级频控

1. 固定同一用户和画像连续请求。
2. 每次对胜出广告触发曝光。
3. 达到策略频控上限后再次请求。
4. 检查“超过频控上限”数量，并确认原胜出广告被替换。

频控统计来自过去 24 小时该用户的真实有效曝光，不读取广告表中的全局累计数。

### 2.4 库存与投放管理

1. 在“投放”搜索广告 ID。
2. 修改出价或暂停广告，再发起一次请求验证结果变化。
3. 修改后恢复原值。
4. 在“最近操作审计”确认修改与恢复各有一条记录。
5. 修改计划日预算，系统会阻止预算低于已预占和已扣费消耗。
6. 修改广告位底价或拍卖方式，下一次请求立即使用新配置。

### 2.5 策略版本

1. 在“策略”调整召回、截断或权重参数。
2. 保存为草稿，确认生产流量没有立刻变化。
3. 在版本列表中激活草稿。
4. 调用不带 `strategy` 字段的服务端请求。
5. 确认响应 `strategyVersion` 为新激活版本。

请求显式传入 `strategy` 时标记为 `request_override`，适合调试，不代表生产发布。

### 2.6 A/B 实验

1. 使用多个不同用户 ID 发起不带策略覆盖的请求。
2. 检查响应中的 `experiment.variant`、`bucket` 和 `applied`。
3. 相同用户重复请求应保持同一桶位。
4. 在“实验”查看对照/实验请求、填充、eCPM、CTR 和 CVR。

本地样本不足时不应据此得出统计显著结论。

## 3. 健康检查解释

“运行健康”中的一致性风险应为 0：

- 无计划广告、无广告主计划：外键或导入数据异常。
- 孤立预算预占：预占缺少对应请求。
- 过期未释放预占：需要点击“释放过期预占”。
- 超日预算计划、负余额账户：资金安全异常。
- 生产策略非唯一：激活策略不是恰好一个。
- 孤立实验分桶：实验记录缺少请求。

## 4. 数据库注意事项

本地 D1 文件位于 `local-data/v3/d1/miniflare-D1DatabaseObject/`，排除 `metadata.sqlite` 后的长文件名数据库为当前应用库。

普通业务表可以使用 SQLite 工具查看。以下表禁止直接修改或删除历史：

- `billing_ledger`
- `auction_logs`
- `ad_events`
- `operation_audit_logs`
- `experiment_assignments`

数据库触发器会拒绝这些操作。业务修正应追加退款、调账或新的操作记录。

## 5. 核心接口

```text
POST /api/ad/request                 广告决策
GET  /api/ad/request                 最近请求
POST /api/events/{type}              事件上报
GET  /api/events?requestId=...       事件查询
GET  /api/ops/request/{requestId}    请求全链路
GET  /api/ops/health                 运行健康
POST /api/ops/health                 释放过期预算预占
GET  /api/ops/risk                   风险扫描
GET/PATCH /api/inventory             广告库存
GET/PATCH /api/campaigns             投放计划
GET/PATCH /api/placements            广告位与底价
GET/POST/PATCH /api/strategies       策略版本
GET  /api/experiments                实验指标
GET  /api/billing/ledger             资金与拍卖流水
GET  /api/healthz                    服务与数据库就绪探针
```

所有管理修改使用 `Idempotency-Key` 防止重复操作，并写入操作审计。当前 Demo 的操作者通过 `X-Operator` 标识；商用部署还需要接入真实身份认证和角色权限。
